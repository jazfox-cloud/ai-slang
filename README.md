# AI Slang & Humanizer Hub

[AI Slang](https://ai-slang.com/) is a glossary for understanding the language around AI: community slang, product vocabulary, and technical terms. Read definitions, usage examples, source notes, and related entries in context.

## Explore the glossary

| Start here | What you can read |
| --- | --- |
| [AI Slang dictionary](https://ai-slang.com/) | Browse the published term cards and open individual entries. |
| [Slop](https://ai-slang.com/terms/slop) | Meaning, usage examples, and the distinction between AI slop and other low-value content. |
| [Vibe Coding](https://ai-slang.com/terms/vibe-coding) | Origin, examples, and how the term differs from ordinary AI-assisted coding. |
| [Editorial policy](https://ai-slang.com/editorial-policy) | How references, source types, uncertainty, and corrections are handled. |

A useful reading path is to open a term, read its examples, inspect the source note and last-checked date, then follow a related term. Community language and editorial interpretations can change; use the references and dates to judge the context.

The `AI_TASTE` and `TREND` labels are editorial signals, not measured search-volume statistics or proof that a piece of writing was generated by AI.

## Existing resources in this repository

- [Structured glossary data](src/data/slangs.js): definitions, examples, source types, reference URLs, last-checked dates, and related terms.
- [Static-page generator](scripts/build-static-pages.mjs): builds the individual glossary pages from the shared data.
- [Browser implementation](src/app.js) and [Humanizer API](functions/api/humanize.js): include rule-based rewriting and optional DeepSeek integration. The rewriting score is a heuristic, not a validated AI-authorship detector.

## Implementation notes

The original MVP setup documentation follows. It describes the repository's implementation and configuration; it is not confirmation that every production interaction is working.

Minimal MVP for an AI slang dictionary and AI-text humanizer.

## What is included

- Static dictionary UI with searchable slang entries.
- Humanizer UI with local rule-based fallback.
- Cloudflare Pages Function for `/api/humanize`.
- D1 schema draft for the later database-backed version.

## Local preview

```bash
npm run build:static
npm run build:deploy
npm run dev
```

Open `http://localhost:8788`.

The local static server uses the browser fallback humanizer. On Cloudflare Pages, `/functions/api/humanize.js` can call DeepSeek when `DEEPSEEK_API_KEY` is configured.

## Static SEO pages

Run this whenever `src/data/slangs.js` changes:

```bash
npm run build:static
```

It generates:

- Static `.html` files under `/terms/`, `/articles/`, and the root policy pages including `terms-of-use.html`.
- Clean public URLs in canonical tags, internal links, and `/sitemap.xml`, such as `/terms/slop` rather than `/terms/slop.html`.
- `/robots.txt` and `/sitemap.xml`.

The default production domain is `https://ai-slang.com`. Set `SITE_URL=https://your-domain.com` before running the build if the production domain changes.

## Cloudflare setup notes

1. Deploy this repo as a Cloudflare Pages project.
2. Build command: `npm run build:deploy`.
3. Build output directory: `dist`.
4. Production branch: `main`.
5. Add custom domain: `ai-slang.com`.
6. Optional redirect domain: add `aislanghub.com` and keep `_redirects` so it points to `ai-slang.com`.
7. Set `DEEPSEEK_API_KEY` as an encrypted environment variable before enabling the live Humanizer API.
8. Optional later step: create a D1 database and apply `schema.sql`.
9. Optional later step: add KV binding `RATE_LIMIT` for durable daily limits.

The deploy build uses an explicit public-file allowlist. Repository-only material under `docs/` and `reports/`, source data, tests, scripts, and configuration files are not copied into `dist/` and are not published as static assets.

## MVP scope

The first version deliberately avoids login, Stripe, X/Twitter monitoring, and automated content generation. Those are better added after the dictionary and humanizer pages prove they can attract clicks.
